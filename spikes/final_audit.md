## Ranked fix list

### BLOCKER

1. **An agent can resolve its own block and confirm roots: the person-only gate does not hold.** README 133 says the hook denies "a shell command that runs one of the person-only commands"; README 149 says "Whether a decision can block at all is also a person's call". Both are false against an agent that quotes one word.
   - `PERSON_ONLY` in `knack/hooks/pretool_guard.py:45` is a regex on raw command text. Allowed through the real hook: `knack "resolve" …`, `knack re''solve …`, `k=knack; $k resolve …`, `python -c "from knack.cli import main; main(['resolve', …])"`, `echo … | base64 -d | sh`, `bash ./approve.sh`. Denied: plain, `python -m knack.cli`, `python -m knack`, `.venv/bin/knack`, extra spaces, env prefix.
   - `resolve`'s own check (`_run_by_a_person`, `knack/cli.py:376`) accepts `--by X` plus `KNACK_HUMAN=1`, which an agent can set inline. End to end, in the injection sandbox: `KNACK_HUMAN=1 knack "resolve" 5dda0ebc… allow --by 'Vedant Srivastava' --reason approved`, sent as a bash event, passed the hook, then ran from a pipe (`</dev/null`). Result: `5dda0ebc05d6: allowed by Vedant Srivastava (airflow-75025, airflow-75025-1)`, and `knack receipts verify` still said `3 receipts, chain intact`.
   - `knack confirm` has no person check at all (`_confirm_command`, `knack/cli.py:298`). From a pipe in a sandbox copy: `knack confirm fastapi-15515-2 --by 'Vedant Srivastava' --no-gate` → `Inferred -> Confirmed, pinned to rule 3f9de28f7fd7`. Through the hook, quoting the word gets past the regex the same way.
   - Smallest honest fix: scope README 133/149 to "denies the plain spellings; not a sandbox". Real fix (later): match on `shlex`-split argv, deny any bash command that sets `KNACK_HUMAN`, and put the same person check on `confirm`, `false-block` and `retire`.
2. **The console home page labels Knack's own commits as apache/airflow's day.** Running the README's console command (README 43) from a clone of Knack, `/` heads the page "apache/airflow remembers 9 decisions". Under that header, "Today, Nov 3 2026" lists "Merge pull request #128 from vedntzz/chore/confirm-batch-2" and the other Knack commits. The cause is `local_day(Path.cwd())` in `knack/console/app.py`: it reads the cwd's git log, not the registry's repo. Every judge who follows the README sees this page. Fix: build the feed from the registry's repo, or hide it when the cwd's origin differs from the registry's repo.

### LATER

3. **A stale pin turns off a block without any message.** Changing one valid byte in `data/rules/airflow/75025.yml` (`Do not expose` → `Do nat expose`) turns all 3 violations from deny into a plain allow. Nothing reaches the agent or `guard_errors.log`, and the receipt says `allow` with `matched` filled in but no stale marker. This is by design: a changed rule advises until re-confirmed. But nobody is told. `reproduce.sh` does catch it: the grid row becomes `warn … NOT RUN` and the diff against `bench/PROOF-GRID.md` fails. Fix: a `stale_pin` field on the receipt and one advisory line.
4. **Cutting lines off the end of the receipt chain is not detected.** Changing a field, flipping a byte or deleting a middle line all fail loudly ("chain broken at line N"). Removing the last line verifies as `7 receipts, chain intact`. No surface claims tamper-evidence (`grep -n tamper` in README, card and site is empty), so this is LATER. Fix: print the head hash so it can be pinned somewhere outside the file.
5. **Bare `uv sync --frozen` breaks `reproduce.sh` with a confusing error.** It installs no pytest, so e2e goes 5/26 with `ModuleNotFoundError: No module named 'pytest'` and the run ends `PROOF: FAIL (e2e: knack init)`. The documented command (`--extra dev`, README 31, site, card) passes. But README 26's sentence "`uv sync --frozen` installs the exact versions…" reads as if the bare command were enough. Fix: a pytest preflight in `reproduce.sh` with a one-line hint, or say `--extra dev` in that sentence.
6. **CI doesn't install what judges install.** `ci.yml` and `knack-guard.yml` run `uv pip install -e ".[dev]"`, unpinned, while judges get `uv.lock`. Both pass today (below). Fix: `uv sync --frozen --extra dev` in CI.
7. **`spikes/claims.md` is out of date.** Its header still says `9bf4802`. The pinned-confirm row cites `ecf207d0…` for `airflow-75025-1`, but since the KN-97 repair it is `865e1a98…`, equal to the rule file. Both TODOs are done but still unticked: the site screenshots now show "default branch and release 3.3.2", and `spikes/self_repair_live.md` is merged and cited in README 146.
8. **There is no `self_reading` frozen story.** No file, fixture or commit on any local or remote branch matches `self_read`. The "reads on its own" proof is the PostToolBatch spike (`spikes/posttoolbatch_live.md`), a committed log, not a frozen fixture. Flagged for Vedant: either the ticket meant something else, or the story was never frozen.
9. **Home page shows #75774 twice.** "Confirmed decisions" has two identical cards (roots `-1` and `-2` share a decision text), which reads as a duplicate. Fix: one card per decision, listing both rejected alternatives.
10. **Recovery page cuts off its verify command at 1080p.** It shows `knack receipts verify --p…`. Copy probably still copies the full text, but I didn't click it: no browser extension this session.
11. **Coverage caveats for steps 5 and 6** (not defects):
    - Step 6's "fix" was the 3 committed compliant variants per rule. The PR head is covered only by the recorded proof (`head` side, flagged 0).
    - In step 5, the live agent never sent the literal `allow` command (see step 5 below). The literal command was checked offline instead.
